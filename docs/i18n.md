# Interface localization

The interface supports Spanish (`es`, the initial language) and English (`en`).
The selector is available in both headers and the footer. The choice is saved
under `muvia.language`; country selection uses its own `muvia.market` preference.

## Dictionaries and presentation

`src/app/core/services/i18n/dictionaries/` contains matching `es/` and `en/`
directories. Each language has a JSON file for each namespace: `app`, `auth`,
`catalog`, `categories`, `common`, `errors`, `files`, `home`, `navigation`,
`pagination`, `search`, `seller`, and `staging`.

For example, `es/catalog.json` and `en/catalog.json` contain the same dotted
`catalog.*` keys. Keep shared interface copy in `common.json` and feature-specific
copy in the corresponding module. Keys retain their prefixes; components do not
need to know which file owns a translation.

Each language's `index.ts` imports and combines its JSON modules into one typed
dictionary. The service imports these entry points, preserving compile-time key
checking. Both languages are bundled for synchronous translation, including
prerendering, without a translation API or extra dependency. Splitting the source
files improves maintenance; it does not introduce lazy loading.

Add translations to the corresponding JSON file in both languages. If adding a
namespace, create its JSON file and include it in both `index.ts` entry points.

Use typed keys for new interface copy:

```html
{{ 'common.language' | translate }}
{{ 'catalog.productCount.other' | translate: { count: total() } }}
```

In TypeScript, inject `I18nService` and call `t(key, parameters)` inside a computed
value when the text needs to react to language changes. Add both `.one` and
`.other` entries for counts and choose the appropriate key for Spanish/English.
Interpolation inserts plain text; do not bind dictionary values to `innerHTML`.

`uiText` is a compatibility presenter for reviewed validation and error messages
already stored as Spanish text in forms and `AppError`. It looks up only known
dictionary messages, including explicit file-message patterns. It does not
translate arbitrary backend text. Normalize errors with `toAppError` before
presenting them; backend codes and telemetry retain their existing contracts.

## Content boundaries

Translate platform labels, hints, navigation, errors, and accessibility text.
Render seller titles, descriptions, keywords, material/color values, business
names, social-link names, and file names directly. Never pipe seller content
through `translate` or `uiText`, even if it happens to match an interface message.

`categoryName` translates the known taxonomy by category code. Older catalog
summaries without a code use a lookup of known platform category labels. Add
dictionary entries when adding a platform category; unknown codes retain the API label.
`countryName` uses `Intl.DisplayNames` with the selected interface language.
Search interpretation uses structured category/dimension fields and known
material labels; unknown search vocabulary is preserved.

## Country, currency, and rendering

`MarketService.locale()` derives the interface language and selected country
(for example `en-BO`). Changing language changes formatting, not the selected
market, product amount, or currency. Use `ProductPrice` for monetary values and
keep each amount paired with the currency returned by the API.

Prerendered HTML starts in Spanish. The saved browser preference is restored
after the initial render to keep Angular hydration consistent. Language changes
also update the document language, title, and description. Blocked browser
storage leaves the current-session selector usable.

Changing the interface language does not translate catalog content or guarantee
cross-language search matches. These are separate product capabilities.

## Validation

The i18n tests check dictionary parity, interpolation parameters, persistence,
blocked storage, metadata, safe error presentation, market independence, and
seller-content preservation. Run the frontend test suite and production build
after changing translations.
